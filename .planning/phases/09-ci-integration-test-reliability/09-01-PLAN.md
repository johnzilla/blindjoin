<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → bitcoincore.org | Tarball + SHA256SUMS + SHA256SUMS.asc downloaded over HTTPS; integrity gated by PGP signature on SHA256SUMS, not by TLS alone |
| GitHub Actions runner → raw.githubusercontent.com (guix.sigs) | achow101.gpg key blob fetched from a SHA-pinned commit; integrity gated by fingerprint match after import |
| GitHub Actions runner → actions/cache (GitHub-hosted blob store) | Cache contents trusted because cache key includes `${{ runner.os }}` and the pinned version string; cache contents replaced by signed-tarball install on cache miss |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | bitcoind tarball download from bitcoincore.org | mitigate | SHA256SUMS verified against achow101 PGP signature (fingerprint `152812300785C96444D3334D17565732E08E5E41`) before the tarball hash is checked; defeats MITM and a hostile bitcoincore.org mirror |
| T-09-02 | Tampering | achow101.gpg key blob from raw.githubusercontent.com | mitigate | SHA-pinned commit of `bitcoin-core/guix.sigs` makes the key fetch content-addressed; after import, `gpg --list-keys --with-colons` is greped for the expected fingerprint — a swapped key in a hostile commit would fail the fingerprint check |
| T-09-03 | Tampering | actions/cache restored blob | mitigate | Cache key includes `${{ runner.os }}` (cross-runner-image collision prevented) and `${{ steps.bitcoind_version.outputs.version }}` (cross-version collision prevented); cache miss path always re-runs the SHA+PGP verification so a poisoned cache slot can be recovered by bumping `.bitcoind-version` |
| T-09-04 | Repudiation | install step provenance in CI logs | accept | actions/cache@SHA + `gpg --verify` outputs are captured in the CI run log; sufficient for postmortem; deeper SLSA-style attestation is out of scope for v1.3 |
| T-09-SC | Tampering | actions/cache@v4 GitHub Action | mitigate | SHA-pinned (`0057852bfaa89a56745cba8c7296529d2fc39830 # v4.3.0`) per Phase 6 supply-chain discipline; same approach as existing actions/checkout, dtolnay/rust-toolchain, Swatinem/rust-cache pins. `actions/cache` is a first-party GitHub org (verified) — no `[ASSUMED]`/`[SUS]` legitimacy checkpoint required |
</threat_model>
