<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tagged-commit → CI runner | The tag's commit time crosses into `SOURCE_DATE_EPOCH`; if the commit time is tampered with (force-push to a tag), the verifier's external rebuild gets a different value → mismatch → real-divergence issue (correct behavior) |
| release-yml → GitHub Releases page | The softprops step uploads 4 assets to GH Releases; without `draft: true`, the upload publishes immediately (D-13 contract); this is intentional |
| build environment → release tarball bytes | RUSTFLAGS + SOURCE_DATE_EPOCH + tar/gzip flags collectively determine the byte content; any leak (e.g., runner-local path in debug info) breaks reproducibility |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-02-01 | Tampering | Build environment leaks runner-local paths into binary | mitigate | Two `--remap-path-prefix` flags in RUSTFLAGS strip `${{ github.workspace }}` and `/home/runner/.cargo` paths from debug info per D-02. Belt-and-suspenders with `strip = "symbols"` from Plan 25-01 (D-07) removes the symbol table entirely. |
| T-25-02-02 | Tampering | `Cargo.lock` modified at runtime by cargo regenerating it silently | mitigate | `--locked` flag (D-05) causes cargo to exit 101 if `Cargo.lock` is missing or out of sync. CI fails fast; no silent regeneration possible. |
| T-25-02-03 | Tampering | tar/gzip embed runner-local mtime / user identity / filename → divergent bytes across rebuilds | mitigate | D-06's 5 flags (--sort=name, --owner=0, --group=0, --numeric-owner, --mtime="@$SOURCE_DATE_EPOCH") and `gzip -n` collectively strip every known nondeterminism source per reproducible-builds.org archive guidance. |
| T-25-02-04 | Information Disclosure | Comment block in release.yml leaks the literal `ubuntu-latest` token (audit grep would fail) | mitigate | Plan 22-04 paraphrasing discipline applies: comments use "rolling-release runner alias" or "unpinned runner image" instead. Acceptance criteria asserts `! grep -E '^[^#]*ubuntu-latest' build-job-stanza`. |
| T-25-02-05 | Repudiation | Orphaned `draft: true` (D-13 cleanup) causes verifier in 25-04 to fail `gh release download` without `--draft` flag, masking the post-PGP-deferral inconsistency | mitigate | D-13 cleanup IS the fix — removing `draft: true` makes every tag push produce a published (non-draft) release; verifier `gh release download` works without `--draft` + GITHUB_TOKEN gymnastics. |
| T-25-02-06 | Denial of Service | `--locked` causes CI to fail on every Cargo.lock change without explicit commit | accept | This is the intended behavior. If contributors update deps without regenerating Cargo.lock, CI surfaces the gap immediately. Trade-off accepted. |
| T-25-02-07 | Information Disclosure | SOURCE_DATE_EPOCH derived from tag commit time is observable in panic message timestamps after path-strip | accept | The committer time is already public via git log; embedding it in debug info adds no new information disclosure beyond what `git log` provides. |
</threat_model>
