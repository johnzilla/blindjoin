<objective>
Create `.github/workflows/reproducible-verify.yml` — the scheduled monthly verifier that closes REPRO-03. The workflow runs on the 1st of each month at 07:00 UTC on a fresh `ubuntu-24.04` runner, captures `${ImageVersion}`, downloads the latest release tarball + cosign bundle, re-verifies the cosign signature (Phase 24 SIGN-01 inheritance), checks out the source at the release tag, rebuilds via the REPRO-01 Recipe (using the SAME deterministic env + tar/gzip pipeline as `release.yml`), compares `sha256sum`, and on mismatch opens a `[reproducibility-regression]` issue per D-12's two-title scheme (low-severity runner-image drift vs HIGH-severity sha256 mismatch on identical ImageVersion).

Purpose: REPRO-03 requires the continuous verifier that proves blindjoin's reproducibility claim every month rather than only at ship time. The two-title issue scheme distinguishes a benign GitHub runner-image rotation from a real supply-chain signal. The verifier exiting 1 always on mismatch (RESEARCH Open Question #3) is the precondition for D-14 registry submission — a silenced workflow undermines the registry's "≥1 green monthly cycle" gate.

Output: 1 new file (`.github/workflows/reproducible-verify.yml`, ~110-150 lines).
</objective>
