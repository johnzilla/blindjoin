Create shared/src/token.rs implementing compute_blind_token_message:
```rust
use bitcoin::Script;
use sha2::{Sha256, Digest};

/// Compute the blind token message for a CoinJoin output.
///
/// Format: SHA-256("blindjoin-v1" || script_pubkey_bytes || amount_sats_le64)
///
/// CANONICAL RULES (must match between coordinator and client):
/// - script_pubkey_bytes = output_script.as_bytes() — raw script bytes WITHOUT CompactSize length prefix
/// - amount_sats_le64 = amount_sats.to_le_bytes() — 8 bytes, little-endian u64
///
/// This function MUST live in shared/ and be used by both coordinator and client
/// to guarantee byte-identical output.
pub fn compute_blind_token_message(output_script: &Script, amount_sats: u64) -> [u8; 32] {
    let mut hasher = Sha256::new();
    hasher.update(b"blindjoin-v1");
    hasher.update(output_script.as_bytes());
    hasher.update(amount_sats.to_le_bytes());
    hasher.finalize().into()
}
```

mod tests {

    fn compute_blind_token_message_deterministic() {
        // P2WPKH script: OP_0 <20-byte-hash>
        let script = ScriptBuf::from_bytes(vec![
            0x00, 0x14,  // OP_0, PUSH20
            0x89, 0xab, 0xcd, 0xef, 0xab, 0xcd, 0xef, 0xab,
            0xcd, 0xef, 0xab, 0xcd, 0xef, 0xab, 0xcd, 0xef,
            0xab, 0xcd, 0xef, 0xab,
        ]);
        let amount_sats: u64 = 1_000_000;
        let result1 = compute_blind_token_message(&script, amount_sats);
        let result2 = compute_blind_token_message(&script, amount_sats);
        assert_eq!(result1, result2);
        assert_eq!(result1.len(), 32);
    }

    #[test]
    fn compute_blind_token_message_different_amounts() {
        let script = ScriptBuf::from_bytes(vec![0x00, 0x14, 0x00; 22][..22].to_vec());

        let r2 = compute_blind_token_message(&script, 1_000_001);

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→shared types | Client-produced JSON is deserialized into shared structs — untrusted field values |
| shared types→coordinator | Protocol structs used as coordinator handler inputs — all values must be validated at use site, not at deserialization |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | compute_blind_token_message | mitigate | Function lives in shared/ and is used identically by both sides; tested with known vectors to prevent divergence |
| T-01-02 | Information Disclosure | ErrorCode serialization | accept | Error codes are machine-readable but reveal no PII — only protocol state (UTXO_SPENT, WRONG_PHASE, etc.) |
| T-01-03 | Spoofing | InputRegRequest.utxo_outpoint | accept | Shared types perform no validation — validation happens in coordinator/bitcoin/utxo.rs (plan 03); string format is untrusted until parsed |
| T-01-04 | Tampering | serde unknown fields | mitigate | No deny_unknown_fields per D-06; unknown fields silently dropped — this is intentional for forward compat; no security risk as coordinator validates all consumed fields |
</threat_model>
