  <how-to-verify>
    On github.com, navigate to: **Settings → Branches → Branch protection rules → `main`** (create the rule if it does not exist).

    Verify or set the following:

    1. ✅ **Require a pull request before merging** — checked.
    2. ✅ **Require approvals** — at least 1 approval required.
    3. ✅ **Require review from Code Owners** — CHECKED. (This is the load-bearing setting that activates the CODEOWNERS file from Plan 01.)
    4. ❌ **Allow specified actors to bypass required pull requests** — leave unchecked, or if any bypass list is configured, confirm it does NOT include the maintainer's own account except for documented emergency-only use.
    5. ❌ **Do not allow bypassing the above settings** — under "Restrictions" or "Bypass list": "Allow administrators to bypass required reviews" must be UNCHECKED. (RESEARCH.md §9 row 1 — this is the supply-chain-critical setting; with it checked the maintainer can self-merge a malicious digest bump via admin override.)

    Verify the result programmatically (RESEARCH.md §8 line 833 + §10 line 951):

    ```bash
    # Returns `true` when "Require review from Code Owners" is checked.
    gh api repos/:owner/:repo/branches/main/protection \
      --jq '.required_pull_request_reviews.require_code_owner_reviews'
    # Expect: true

    # Returns the admin-bypass setting; expect `false` (admin override DISABLED).
    gh api repos/:owner/:repo/branches/main/protection \
      --jq '.enforce_admins.enabled'
    # Expect: true (means rules are enforced for admins too)
    ```

    Negative-path rehearsal (optional but recommended): open a draft PR from a fork or a non-CODEOWNERS account that touches `docker/digests.txt`. Confirm the merge button is blocked with "Code owners review required" until a CODEOWNERS reviewer approves. (RESEARCH.md §8 line 830 cite (d).)
  </how-to-verify>

    Run the full deliberately-stale-digest E2E test from RESEARCH.md §8 lines 845-878:

    ```bash
    # 1. Stale the manifest on a throwaway branch (flip the trailing hex char).
    git checkout -b test/digest-drift-e2e-$(date +%s)
    sed -i.bak '/^debian:/s/[0-9]$/0/; /^debian:/s/[a-f]$/0/' docker/digests.txt
    git commit -am "test: deliberately stale debian digest for drift rehearsal"
    git push -u origin HEAD

    # 2. Fire the drift workflow against the stale branch.
    gh workflow run digest-drift-check.yml --ref $(git branch --show-current)

    # 3. Watch the run; expect: ✗ DRIFT, new issue opened, label digest-drift applied.
    gh run watch

    # 4. Verify exactly 1 open digest-drift issue.
    test "$(gh issue list --label digest-drift --state open --json number --jq 'length')" = "1" && echo "SC#2a PASS"

    # 5. Re-fire the workflow with the same drift.
    gh workflow run digest-drift-check.yml --ref $(git branch --show-current)
    gh run watch

    # 6. Verify still exactly 1 open digest-drift issue (idempotency — Pitfall 9).
    test "$(gh issue list --label digest-drift --state open --json number --jq 'length')" = "1" && echo "SC#2b PASS (idempotent)"

    # 7. Cleanup — close the test issue, restore manifest on main, delete branch.
    DRIFT_NUM=$(gh issue list --label digest-drift --state open --json number --jq '.[0].number')
    gh issue close "$DRIFT_NUM" --comment "Closing — drift was Phase 22 SC#2 rehearsal."
    git checkout main && git push origin --delete test/digest-drift-e2e-*
    ```
