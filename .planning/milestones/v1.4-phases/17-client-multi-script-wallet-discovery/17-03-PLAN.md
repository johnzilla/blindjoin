**CONTEXT D-73 field-name correction (load-bearing — RESEARCH Pitfall 5):**

CONTEXT.md §D-73 shows: `BlindjoinRecord { version: String, ... }` with `default_legacy_version() -> "0.1.0"`.

**THIS WOULD BREAK SILENTLY ON EVERY v1.4 COORDINATOR.** Phase 16-03 (commit `d1a1912`, dated 2026-05-30) compactified the PKARR wire field name from `version` to `v` for byte-budget reasons (verified at `coordinator/src/discovery/pkarr_pub.rs:98-108` — the production record emits `"v": "0.2.0"`, NOT `"version": "0.2.0"`).

A `#[derive(Deserialize)] struct BlindjoinRecord { version: String, ... }` against a Phase-16-produced wire record would MISS the field (no `version` key on the wire — only `v`), and the `#[serde(default)]` would produce `"0.1.0"` — making EVERY v1.4 coordinator look like a v1.3 legacy coordinator. The compat shim would fire on every connection; WALLET-04 would silently fail in the WRONG DIRECTION (v1.4 client emits v=1 envelopes to v1.4 coordinators that expect v=2, coordinator's v=1 arm validates against the wrong sighash math and rejects).

**Source of truth:** `coordinator/src/discovery/pkarr_pub.rs::build_coordinator_packet` lines 89-108 (Phase 16-03 commit `d1a1912`):
```rust
let record = serde_json::json!({
    "type": "blindjoin-coordinator",
    "v": "0.2.0",                              // <-- compact field name
    "onion": coordinator_addr,
    "n": "signet",
    "ds": denomination_sats,
    "mp": min_participants,
    "st": status,
    "sst": supported.join(","),                // <-- CSV alphabetical: "p2sh-p2wpkh,p2tr,p2wpkh"
    "ost": output_script_type,                 // <-- kebab-case scalar: "p2wpkh"
});
```

**Required fix in this plan:** the `BlindjoinRecord` struct uses `#[serde(rename = "v", default = "default_legacy_version")] pub version: String`. The `onion`, `sst`, `ost` field names are 1:1 with the wire keys (no renames needed). Document the v→`v` rename in an inline doc-comment so future refactors don't lose the binding.
