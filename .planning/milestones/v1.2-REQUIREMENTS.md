# Requirements: blindjoin (v1.2 snapshot)

**Defined:** 2026-05-26
**Source-of-truth:** `.planning/BACKLOG.md` §B-01 (Public-endpoint hardening) + `.planning/phases/08-public-endpoint-hardening/08-CONTEXT.md` decisions D-01 through D-06.

## v1.2 Requirements

v1.2 was a single-phase milestone (Phase 8) that promoted BACKLOG entry **B-01: Public-endpoint hardening** directly to phase planning. Unlike v1.1, v1.2 did not generate a parallel `REQ-XX` numbering scheme — the design contract lived in `08-CONTEXT.md` decisions and was tracked via Phase 8's must_haves block.

The validated deliverables (per `.planning/PROJECT.md` "Validated Requirements" section):

- [x] Per-route rate limiting on coordinator HTTP API (read endpoints: 60/min; write endpoints: 30/min) with HTTP 429 + `Retry-After` header + `RATE_LIMITED` JSON envelope
- [x] Uniform request timeout returning HTTP 408 honoring `request_timeout_secs`
- [x] Tor accept-loop connection cap via `tokio::sync::Semaphore` (default 256) wrapped in `ConnectionGuard` RAII type
- [x] Operator-tunable knobs via `coordinator.toml` and `BLINDJOIN__COORDINATOR__*` env-var overrides; all knobs validated at startup via `CoordinatorConfig::validate()`
- [x] `GlobalKeyExtractor` used for rate limiting (Tor-safe by design — `PeerIpKeyExtractor` would have broken under Tor's single-source-IP property)
- [x] Release builds refuse to start in clearnet mode unless `BLINDJOIN_ALLOW_CLEARNET=1` is explicitly set

## Future Requirements

Deferred from v1.2 scope:

- **Tor-mode integration harness** — a harness that spawns the coordinator with `tor_mode=true` and a test client opening ≥257 concurrent `.onion` streams, asserting the 257th connection parks until a permit is released. Static coverage was achieved via grep audits in Phase 8 Plan 03; the runtime closure is deferred to v1.4+. See `.planning/phases/v1.2-phases/08-public-endpoint-hardening/08-HUMAN-UAT.md` item 3 (`result: deferred`).

## Out of Scope (Explicit)

| Feature | Reason |
|---------|--------|
| Per-peer throttling on Tor | Architecturally impossible — hidden-service streams carry no peer identity. PR description must distinguish "DoS mitigation" from "sybil prevention." |
| Sybil prevention beyond BIP-322 ownership proofs | Sybil resistance is per-input UTXO control proof (unchanged from v1.0), not per-peer rate-limiting. |
| Per-IP throttling for clearnet mode | Clearnet is dev/test only (production is `tor_mode = true`). Marginal value. |
| Prometheus / Grafana metrics | Optional, not a blocker for production readiness. |
