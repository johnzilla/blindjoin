Purpose: bdk_wallet 2.3.0's `SignOptions::default()` sets `trust_witness_utxo: false`, which causes wallet/mod.rs:1884-1893 to return `SignerError::MissingNonWitnessUtxo` for any non-taproot, non-finalized PSBT input lacking `non_witness_utxo`. The client populates only `witness_utxo` (from `self.utxo_value_sats`), so signing currently fails with `Missing non-witness UTXO`. This blocked Plan 11-02's canonical-first unmute on the 4th orthogonal blocker (per 11-02-SUMMARY §"Failure Diagnosis"). Option A is contextually safe because `witness_utxo.value` originates inside the client from a trusted regtest RPC, not from an untrusted counterparty PSBT.

  Enforcement (wallet/mod.rs:1884-1893):
    if !sign_options.trust_witness_utxo
        && psbt.inputs.iter()
            .filter(|i| i.final_script_witness.is_none() && i.final_script_sig.is_none())
            .filter(|i| i.tap_internal_key.is_none() && i.tap_merkle_root.is_none())

No other SignOptions field needs changing (per 12-RESEARCH.md §"Other SignOptions flags — interaction risk"): try_finalize: true and allow_grinding: true are benign defaults for P2WPKH; allow_all_sighashes: false is correct (we use SIGHASH_ALL); assume_height: None is correct (no timelocks); taproot fields are irrelevant for P2WPKH inputs.
