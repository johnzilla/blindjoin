# Milestone v1.4: BIP-322 Multi-Script Support

**Status:** ✅ SHIPPED 2026-05-31
**Phases:** 14-18
**Total Plans:** 15

## Overview

Broadened CoinJoin participation from P2WPKH-only to P2WPKH + P2TR + P2SH-P2WPKH UTXOs, eliminating the `is_p2wpkh()` registration gate and making the "forward-compatible with all address types" claim in `PROJECT.md` match reality. Phase 14 ran two timeboxed Sprint-0 spikes (`bip322` crate viability + bdk_wallet 2.3 P2TR sign PoC) on quarantined branches and ratified an ADR resolving all 4 Open Decisions before any production code was written. Phases 15-17 landed the shared crate contract, coordinator integration + advertisement, and client wallet + fail-fast discovery. Phase 18 closed the milestone with a mixed-script E2E acceptance gate, liquidity-bot multi-script support, and a v1.3 ↔ v1.4 compatibility gate against a pinned v1.3 binary (SHA `05f21438`).

**Depends on**: Phase 15 (shared crate contract stable).
**Requirements**: ADVERT-01, ADVERT-02, ADVERT-03
**Plans**: 3/3 complete

Plans:

- [x] 16-01: BipConfig struct + validate() + InfoResponse wire-format extension + get_info handler (wire/config-first atomic commit per CD-10 / REPAIR-01 lesson #1) — ADVERT-01
- [x] 16-02: validate_utxo dispatcher swap + CRIT-01 cross-check + multi_script_validate.rs (9 D-54 tests) + fund_regtest_typed helper + CI crit-01-grep-check job — ADVERT-01, ADVERT-03
- [x] 16-03: PKARR record v0.2.0 with `sst` + `ost` fields + 220-byte budget regression gate (`coordinator_packet_under_220_byte_budget`) — ADVERT-02

**Details:**

Top-level `BipConfig { allow_p2wpkh, allow_p2tr, allow_p2sh_p2wpkh, output_script_type }` on `CoordinatorConfig` per D-38 with fail-fast `validate()` (rejects all-false; rejects `output_script_type` not in allowed set). `shared::protocol::InfoResponse` extended with `supported_script_types: Vec<ScriptType>` + `output_script_type: ScriptType`, both gated by `#[serde(default = "default_legacy_*")]` for v1.3↔v1.4 bidirectional compat per D-42. `validate_utxo` linear call to `verify_bip322_simple(...)` replaced with a `match proof.version { 1 => v1_path, 2 => v2_path, _ => Err(UnsupportedProofVersion) }` dispatcher; BOTH branches derive `ScriptType` from on-chain `script_pubkey` via `shared::bip322::detect_script_type` (the load-bearing CRIT-01 invariant) and check `BipConfig::allows` BEFORE calling `shared::bip322::verify_simple`; the v=2 arm additionally cross-checks `declared != derived` and returns `Bip322Error::ScriptTypeMismatch` BEFORE verify_simple. `crit-01-grep-check` CI job greps for the literal token `CRIT-01` in `coordinator/src/bitcoin/utxo.rs` (fails below 2 occurrences). PKARR JSON schema bumped from `version="0.1.0"` (verbose) to `v="0.2.0"` (compact) AND adds `sst` (supported types CSV in alphabetical canonical order) + `ost` (output script type single kebab-case string); **B3 compact-name migration** in the same commit (5 verbose fields compacted: `version → v`, `denomination_sats → ds`, `min_participants → mp`, `status → st`, `network → n` — saves ~56 bytes). Two CI byte-budget regression gates: production-onion at **209 bytes** (62-byte real Tor v3 .onion + all-3 CSV; 11-byte headroom), dev-mode at **161 bytes** (14-byte localhost; 39-byte headroom). New `fund_regtest_typed` helper + `TypedUtxoHandle` per RESEARCH Pitfall 6 funds per-script-type regtest UTXOs deriving each SecretKey in pure rust-bitcoin first then computing SPK + Address ourselves (hermetic, NO `dumpprivkey` roundtrip).

- [x] 17-03: WALLET-03 + WALLET-04 (discovery) — CoordinatorCapabilities + DiscoveryError + extended discover_coordinator + Pitfall 5 BlindjoinRecord `v`-field rename + 9 D-78 acceptance-gate tests

**Details:**

## Milestone Summary

**Cross-Phase Invariant:** v1.3 P2WPKH-only `full_round::*` integration tests remained green at **every** v1.4 phase boundary (8/8 PASS). This was the rollback safety net inherited from v1.3 REPAIR-01 forensics — explicit in every phase's success criteria #5.

**Key Decisions:**

- Decision #1 — ACCEPTED ADOPT `bip322 = "=0.0.10"` over extending the custom impl (Rationale: Sprint-0-A returned GO across all 3 D-02 gates: bitcoin v0.32.8 transitive pin, cargo audit clean, 26-LOC zero-lossy adapter; 3 new transitives `bip322`, `snafu`, `snafu-derive` accepted)
- Decision #2 — ACCEPTED mixed rounds (Rationale: one queue accepts P2WPKH + P2TR + P2SH-P2WPKH inputs together; outputs remain single-script-type per round per operator config; no per-script-type minimum-participant gate; coordinator advertises supported set only, not per-round counts — exact partition vector would leak correlation)
- Decision #3 — ACCEPTED B2 base64 PSBT-input shape with `version: u8` envelope (Rationale: v1.4 `OwnershipProof` carries `psbt_input_b64: String` + `version: u8` where 1 = v1.3 shape, 2 = v1.4 PSBT shape; wire-format roundtrip test shipped FIRST per v1.3 REPAIR-01 lesson #1)
- Decision #4 — ACCEPTED bdk path for P2TR sign (Rationale: Sprint-0-B PASS — bdk_wallet 2.3 produces a valid 64-byte Schnorr keypath witness for BIP-322 P2TR PSBTs; D-15 80-LOC manual fallback retired for v1.4, stays on the books as a v1.5 swap target)
- Phase 14 ran spikes on quarantined branches (D-21 structural invariant: zero production-code commits from a gating ADR phase) — pattern worth repeating when load-bearing decisions are unresolved
- Dispatcher-only public surface on `shared::bip322` (D-27) — makes V1.4-CRIT-01 spoofing vector **statically unreachable** at the type level; load-bearing per-script-type witness sigs cannot be bypassed by client-declared `script_type`
- CRIT-01 cross-check derives `ScriptType` from on-chain `script_pubkey`, not from client declaration — non-negotiable invariant, enforced by 2 CI grep gates (coordinator + client side, must have ≥1 `CRIT-01` token each)
- B3 PKARR compact field names landed in the same atomic commit as the v0.2.0 schema bump (Rationale: 56-byte savings preserved 11 bytes of headroom under the 220-byte budget for the all-3 supported_types CSV; a 4th script type in v1.5 will need a new encoding strategy)
- 26-LOC `bip322` crate adapter ported verbatim from `sprint-0-A.md:145-175` per D-26 — zero rewriting, zero `unwrap_or*`, zero field-shape squashing; preserves the spike's audited shape
- bdk_wallet 2.3 finalizes single-key taproot keyspend into `psbt.inputs[0].final_script_witness[0]` NOT `tap_key_sig` — Sprint-0-B finding carried forward into WALLET-02 witness extraction (parallels existing P2WPKH fallback pattern at `client/src/wallet.rs:277-285`)
- `BdkClientWallet::generate` uses **literal** descriptor templates with coin=0' across all networks — NOT bdk_wallet's `Bip84/86/49` helpers (Rationale: helpers auto-select coin=1' on testnet/signet which would break v1.3 byte-equivalence and the cross-phase invariant; documented inline per RESEARCH Pitfall 2)
- WALLET-04 compat-shim direction is **one-way** (v1.4 client ↔ v1.3 coordinator); the v1.3 client ↔ v1.4 coordinator cell is verified by running an actual pinned v1.3 binary (SHA `05f21438`) against the v1.4 coordinator — not by emulation in test code

**Issues Resolved:**

- Eliminated the `is_p2wpkh()` hard gate at `coordinator/src/bitcoin/utxo.rs:119` (v1.0 carry-forward) — coordinator now accepts all 3 script types via the version-dispatcher
- V1.4-CRIT-01 (script-type spoofing) statically mitigated at the `shared/` crate boundary via dispatcher-only public surface + on-chain cross-check; defense-in-depth at coordinator AND client side via CRIT-01 grep gates
- V1.4-CRIT-02 (silent sighash regressions) caught at sign time by routing through the `bip322` crate's verify-side internal `util::create_to_sign` — exposed 2 v1.3 latent bugs in `build_bip322_to_sign` (`Version::TWO` should be `Version(0)`; `ScriptBuf::new_op_return([])` should be bare `OP_RETURN`) auto-fixed in Plan 15-03 Task 2
- V1.4-MIN-02 uniform-script fingerprint mitigated by liquidity-bot per-round rotation
- V1.4-MOD-03 fail-fast discovery — v1.4 client rejects mismatched coordinators BEFORE opening a Tor circuit (saves circuit cost + improves UX)
- Pitfall 5 (PKARR field rename mismatch) — without `#[serde(rename = "v")]` on the v1.4 client decoder, every v1.4 coordinator would silently appear legacy on every connection. Caught and corrected in Plan 17-03 Task 1
- Pitfall 1 (bare `psbt::Input` on the wire) — encoder uses the FULL BIP-174 PSBT shape so the decoder's `Psbt::deserialize` works; would have surfaced as silent HTTP 400s on every v=2 input registration. Caught and corrected in Plan 17-02
