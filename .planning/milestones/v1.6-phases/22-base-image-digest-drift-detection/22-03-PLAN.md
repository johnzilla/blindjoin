<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tagged-release `push: tags` event → release.yml / docker.yml | Untrusted git ref triggers a release-grade workflow. The composite action's exit code is the supply-chain gate: tag push cannot publish without a valid manifest. |
| docker.yml → ghcr.io | Image push consumes build-args sourced from the canonical manifest. Any drift in the build-arg → Dockerfile ARG name pairing would cause `FROM ${VAR}` to fall back to the floating-tag default — undermining the digest pin. |
| Composite action outputs → docker/build-push-action `build-args:` | YAML-string substitution; no code execution at this boundary. Output values were regex-validated in Plan 02 so they are guaranteed to be `image:tag@sha256:HEX` shape. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-08 | Tampering | release.yml / docker.yml step ordering (malicious PR moves the composite-action step AFTER cargo build / docker buildx so the gate fires too late) | mitigate | CODEOWNERS in Plan 01 maps `.github/actions/read-base-digests/**` but NOT the workflow files themselves. Residual: workflow-file tampering still possible. Carry-forward note for Phase 23: extend CODEOWNERS to cover `.github/workflows/release.yml` + `docker.yml` once cosign signing lands. (RESEARCH.md §9 row 2 partial residual.) |
| T-22-09 | Spoofing | Build-arg name mismatch (`DEBIAN_REF` in workflow vs `DEBIAN_REF` in Dockerfile) silently falls back to floating-tag default | mitigate | Cross-file invariant assertion in Task 2 acceptance criteria — Dockerfile ARG names match `build-args:` keys. Verified at write time and re-asserted in Plan 06 UAT. |
| T-22-10 | Tampering | Third-party SHA-pinned action being rotated via force-push to the same SHA | accept | All third-party actions in modified workflows remain SHA-pinned with `# vX.Y.Z` trailing comments. No new third-party actions introduced. (RESEARCH.md §9 row 3.) |
| T-22-11 | Information Disclosure | Composite action's stdout audit-trail lines logging the parsed digests | accept | Digests are public information (Docker Hub registry data). Not a secret. Logging them is the audit-observability point (RESEARCH.md §5.1 line 568). |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan. Modified workflows use only pre-existing SHA-pinned actions + the new local composite action. |

</threat_model>
