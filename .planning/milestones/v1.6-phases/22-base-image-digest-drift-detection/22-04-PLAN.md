<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions scheduler → drift-check workflow | Cron event triggers a privileged-issue-write workflow daily. The workflow can ONLY create issues (no code push, no image push). |
| drift-check workflow → Docker Hub registry | TLS-secured network call resolving the upstream digest. A successful network MITM would cause a false-positive drift issue (operator notices on triage). |
| drift-check workflow → GitHub Issues API | gh CLI authenticates via `GH_TOKEN = secrets.GITHUB_TOKEN`. Token scope is bounded by the workflow's `permissions:` block (issues: write only). |
| drift-check workflow → release pipeline | The workflow is decoupled from release.yml/docker.yml. A failure in drift-check NEVER blocks a release; it only fails to open an issue. (Loosely coupled by design — Pitfall 8.) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-12 | Spoofing | Workflow file modified to add `gh pr create` (auto-merge digest bump) | mitigate | CODEOWNERS in Plan 01 covers `.github/actions/read-base-digests/**` but NOT this workflow file. Residual: workflow tampering still possible. Carry-forward: extend CODEOWNERS to cover `.github/workflows/digest-drift-check.yml` in Phase 23. (RESEARCH.md §9 row 2 partial residual.) |
| T-22-13 | Tampering | `gh-cli credential misuse` — workflow's `GH_TOKEN` used for an operation outside its declared scope | mitigate | Top-level `permissions:` block declares ONLY `contents: read` + `issues: write`. The token physically cannot perform `gh pr create`, `gh release create`, or any code push. Even if the shell logic were modified, the platform-level permission gate blocks the call. (RESEARCH.md §9 row 4 partial.) |
| T-22-14 | Information Disclosure | Issue body or workflow log leaking secrets | accept-zero-risk | Issue body contains only public information (image tags, digest hexes, registry URLs, workflow run URLs). No access to secrets beyond `GH_TOKEN`, which is bounded by `permissions:`. |
| T-22-15 | Denial of Service | Issue spam from a manifest-race condition (drift detected between manifest update PR merge and the next scheduled run) | accept | Idempotency keyed on upstream hex closes the duplicate-issue spam vector. The race window is the time between manifest merge and next-day cron — acceptable per RESEARCH.md §9 row 4. Manual issue close required. |

| T-22-17 | Denial of Service | Docker Hub rate-limit blocks `docker buildx imagetools inspect` | accept-with-action | Daily cadence + 2 images = 2 calls/day from a GitHub Actions runner IP. Far below Docker Hub's anonymous-pull rate limit. If rate-limiting becomes a problem in production, the carry-forward action is to add a Docker Hub auth step. Not a Phase 22 concern. |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this workflow. Uses only `gh` (preinstalled), `docker buildx imagetools` (preinstalled on ubuntu-24.04), and `bash`. SHA-pinned `actions/checkout` is reused at the project's existing pin. |
