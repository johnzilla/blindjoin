## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-16 | Tampering | A future PR adds `sigstore/cosign-installer@v3` (floating tag) without realizing the gate exists — Pitfall 4 | mitigate | The gate's error message names all 4 actions individually and cites SECURITY.md + PITFALLS.md, so the failing PR author sees exactly what to fix. The gate runs on every push + PR, blocking merge. |
| T-23-17 | Tampering | A future PR adds a fifth sigstore-ecosystem action (e.g., `sigstore/policy-controller-installer`) and the gate's 4-action list silently doesn't cover it | accept | This is the narrow-gate trade-off CONTEXT D-04 chose explicitly. Reviewer of any PR introducing a 5th sigstore action is expected to extend the regex; a v1.7 carry-forward note covers this. |
| T-23-18 | Spoofing | Grep regex bypass via newline / whitespace tricks in workflow YAML (e.g., `uses:↵          sigstore/cosign-installer@v3`) | accept | YAML's `uses:` syntax does not permit line breaks between `uses:` and the action ref (the value is on the same line as the key). `grep -rnPE 'uses:\s*<action>@'` matches with any whitespace between `uses:` and the action — including tab/space variations. No bypass observed in practice. |
| T-23-19 | Repudiation | Gate produces no error message — a PR author sees "ci failed" but can't tell why | mitigate | The gate's `echo "ERROR: ..." >&2` block names ALL 4 target actions + the policy documents to consult. PR author can copy-paste the message into a fix commit. |
| T-23-20 | Denial of Service | grep -P consumes excessive CPU on a huge workflows directory | accept | `.github/workflows/` is <10 files; grep -P completes in <100ms on any modern runner. Out-of-scope concern. |
| T-23-SC | Tampering | npm/pip/cargo installs | n/a | The new job installs no packages. Uses only preinstalled `grep` and the SHA-pinned `actions/checkout`. No package-manager surface. |
