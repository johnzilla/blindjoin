## Phase Details

### Phase 8: Public-endpoint hardening
**Goal**: The coordinator HTTP API resists volume-based denial-of-service when exposed publicly — `/round/register_input` and `/round/sign` cannot be flooded faster than global per-route rate limits permit; slow clients cannot tie up request slots indefinitely; concurrent connection counts at the listener are bounded; all limits are operator-tunable
**Depends on**: Phase 7 (the coordinator DoS hardening that surfaced the public-endpoint exposure)
**Source**: `.planning/BACKLOG.md` §B-01 (promoted 2026-05-26 — see `08-CONTEXT.md` for the design contract)
**Success Criteria** (what must be TRUE):
  1. POST `/round/register_input` returns HTTP 429 + `Retry-After` header + `RATE_LIMITED` JSON envelope when flooded past 30 req/min (write endpoint default)
  2. GET `/info` returns HTTP 429 with the same envelope when flooded past 60 req/min (read endpoint default)
  3. A request that does not complete within `request_timeout_secs` (default 30) returns HTTP 408
  4. Coordinator startup refuses configurations where any knob is outside its validated range
  5. Release builds refuse to bind clearnet unless `BLINDJOIN_ALLOW_CLEARNET=1` is explicitly set
**Plans**: 4 plans

Plans:
- [x] 08-01-PLAN.md — Add `[coordinator]` config knobs + `CoordinatorConfig::validate()` startup gate
- [x] 08-02-PLAN.md — Wire `tower_governor` 0.8 per-route rate limiters (read split / write split / GlobalKeyExtractor)
- [x] 08-03-PLAN.md — Wire `tower_http::timeout::TimeoutLayer` (request timeout → HTTP 408)
- [x] 08-04-PLAN.md — Tor accept-loop connection cap (tokio::sync::Semaphore + ConnectionGuard RAII; 408 slow-body integration test via raw tokio TCP slow-write)

**Code review:** 2 BLOCKER + 6 WARNING findings; all fixed in 7 atomic `fix(08): ...` commits before phase landed (see `08-REVIEW.md`).

**Verification:** 11/11 must-haves verified statically. 3 runtime items deferred to `08-HUMAN-UAT.md` for CI sign-off with bitcoind on PATH:
- Items 1 & 2 closed 2026-05-26 via local runtime proof (Homebrew bitcoind v31.0.0 + `cargo test --test integration rate_limiting::`)
- Item 3 (Tor-mode connection-cap runtime test) deferred to v1.4+ — clearnet test infra cannot exercise the Tor-only semaphore; a dedicated Tor-mode harness is the v1.4+ work item
